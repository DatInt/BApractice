В этом документе содержится описание бизнес-процессов и бизнес-логики внутри онлайн-маркетплейса, а также общее описание архитектуры системы и требований, предъявляемых к ней. 
# Глоссарий

- **Маркетплейс (Marketplace)** - Общее название для системы.
- **Продавец (Seller)** - физическое или юридическое лицо, размещающее товары на маркетплейсе для продажи.
- **Покупатель (Customer)** - пользователь, приобретающий товары на платформе.
- **Каталог товаров (Product Catalog)** - структурированный список всех товаров, представленных на маркетплейсе, включая категории, фильтры и описания.
- **Карточка товара (Product Page)** - детализированная страница с описанием товара: характеристики, цена, фото, наличие, отзывы и кнопка покупки.
- **Корзина (Shopping Cart)** - временное хранилище выбранных покупателем товаров перед оформлением заказа.
- **Оформление заказа (Checkout)** - процесс подтверждения покупки, включая выбор доставки, оплаты и указание данных покупателя.
- **Личный кабинет покупателя (Customer Profile)** - раздел с персональной информацией покупателя, историей заказов, настройками и управлением уведомлениями.
- **Личный кабинет продавца (Seller Profile)** - раздел с информацией о продавце, историей продаж, настройками и управлением рассылкой об акциях и скидках.
- **Служба доставки (Delivery)** - модуль, отвечающий за логистику: отгрузку и доставку заказов.
- **Платежная система (Payment)** - сервис, обрабатывающий онлайн-платежи (банковские карты, электронные кошельки и т.д.).
- **Отзывы и рейтинг (Rating)** - система обратной связи, позволяющая пользователям оценивать товары.
- **Админ-панель (Admin Panel)** - интерфейс для управления платформой: модерация контента, управление пользователями, аналитика, настройки.
- **Поиск и фильтрация (Search)** - функционал для быстрого нахождения нужных товаров по ключевым словам, категориям, цене и другим параметрам.
- **Избранное (Favorites)** - список товаров, сохранённых пользователем для будущих покупок.
- **Уведомления (Notifications)** - сервис, ответственный за информирование пользователей о статусе заказов, акциях, изменениях и т.д.

# Описание заинтересованных сторон

#### Внутренние стейкхолдеры:

- Продукт-менеджер
	Отвечает за развитие и поддержание платформы, координирует внутренние команды для поддержания функциональности и конкурентоспособности маркетплейса.

- Команда разработки (dev, QA, аналитики)
	Непосредственно участвуют в развитии платформы, обеспечивают безопасность, масштабируемость, надежность и ввод новых фич. 

- Служба поддержки
	Помогает пользователям (продавцам и покупателям) эффективно пользоваться платформой, работает с претензиями, обеспечивает связь между конечным пользователем и командой разработки.

- Юридический отдел
	Обеспечивает легальность деятельности маркетплейса, заключает договоры с продавцами и покупателями.

- Финансовый отел
	Занимается финансовым и бухгалтерским учетом, готовит отчетность об эффективности деятельности платформы.

- Отдел маркетинга
	Обеспечивает за рост трафика, SEO, рекламные кампании и PR.

#### Внешние стейкхолдеры:

- Покупатели
	Физическое или юридическое лицо, приобретающее товары/услуги через платформу.

- Продавцы
	Компания или индивидуальный предприниматель, размещающий свои товары на маркетплейсе.

- Логистические партнеры (служба доставки)
	Партнёр, обеспечивающий доставку заказов до покупателя.

- Платежные сервисы
	Финансовый посредник, обеспечивающий оплату между покупателем, маркетплейсом и продавцом.

- Рекламодатели
	Сторонние бизнес-партнеры, заинтересованные в продвижении товаров или сотрудничестве.

- Госорганы
	Контролирующие инстанции (налоговая, Роспотребнадзор, Роскомнадзор и др.).

# Требования к функциональности
##  Функциональные требования (ФТ)
#### Требования к каталогу товаров:

- Каталог товаров отображает карточки товаров для покупателя.
- Продавец может размещать/редактировать/удалять карточку товара из каталога товаров.
- Покупатель может искать товары в каталоге товаров по названию или категории товара.
- Покупатель может настраивать фильтрацию по каталогу товаров для поиска по цене, рейтингу или дате размещения.

#### Требования к карточке товара

- В карточке отображается полная информация о товаре: название, описание, цена, фото, количество, продавца, рейтинг и отзывы.
- Пользователь может добавить товар в корзину или в избранное.
- Продавец может редактировать информацию (название, описание, цену, фото) в карточке товара.
#### Требования к корзине

- Покупатель может добавлять и удалять товары из корзины.
- Система рассчитывает итоговую сумму заказа с учётом количества и скидок.
- Система позволят пользователю выбрать способ оплаты(карта, электронный кошелек) и доставки(курьером, в пункт выдачи) на этапе оформления заказа.

#### Требования к личному кабинету покупателя

- Покупатель может редактировать информацию о себе (имя, фамилия, фото, адрес доставки, способ оплаты)
- Покупатель может посмотреть историю покупок и статус оформленных заказов.
- Покупатель может настроить уведомления об акциях и скидках.

#### Требования к личному кабинету продавца

- Продавец может редактировать информацию о себе (название продавца (имя магазна), описание магазина, фото, карточки товара)
- Продавец может посмотреть информацию о продажах и статус отправленных заказов.
- Продавец может настроить рассылку об акциях и скидках.

#### Требования к аутентификации и авторизации

- Система должна позволять покупателям регистрироваться с использованием электронной почты или телефона и пароля.
- Система должна отправлять подтверждение на email после регистрации.
- Система должна поддерживать вход через OAuth (Google, VK, Яндекс и т.д.).
- Система поддерживает вход в один аккаунт через несколько устройств.

###  Нефункциональные требования (НФТ)
#### Требования к внешним интерфейсам

- Доступ к маркетплейсу осуществляется через веб-браузер (для десктоп и мобильных устройств) или через приложение (для мобильных устройств на базе iOS и Android).
- Для веб-версии реализован адаптивный интерфейс под разное разрешение мониторов.
- Оформление интерфейса маркетплейса должно соответствовать общему стайлгайду (для веб-интерфейса и мобильного приложения)
#### Требования к производительности

- Время отклика пользовательского интерфейса: не более **2 секунд** для 95% запросов при нормальной нагрузке
- Доступность системы (Uptime): не менее 99.9% в месяц (не более 43 минут простоя в месяц).
#### Ограничения

- Продажа товаров через интернет регулируется Гражданским кодексом РФ и Законом о защите прав потребителей.
- Со стороны покупателя необходима согласие с политикой конфиденциальности и согласие пользователя на обработку персональных данных.

![[Pasted image 20260314233620.png]]
```
@startuml
autonumber
actor Customer as "Покупатель"
participant "Web Interface" as UI
participant "Auth Service" as Auth
participant "Database" as DB
participant "Email Service" as Email

Customer -> UI : Открыть страницу регистрации
UI -> Customer : Показать форму регистрации

Customer -> UI : Ввести данные\n(имя, email, пароль)

UI -> Auth : Отправить данные регистрации

Auth -> Auth : Валидация данных

Auth -> DB : Проверить email в базе

Auth -> Email : Отправить письмо подтверждения
Email --> Customer : Email с подтверждением

Auth --> UI : Регистрация успешна
UI --> Customer : Показать сообщение об успешной регистрации

@enduml
```

|---|---|---|

|5|Валидация данных|Auth Service проверяет корректность введенных данных.|
|6|Проверить email в базе|Auth Service отправляет запрос в Database для проверки, существует ли указанный email.|
|7|Email не найден|Database сообщает, что пользователь с таким email не найден.|
|8|Хэшировать пароль|Auth Service выполняет хэширование пароля для безопасного хранения.|
|9|Создать пользователя|Auth Service отправляет запрос в Database на создание нового пользователя.|
|10|Пользователь создан|Database подтверждает успешное создание пользователя.|
|11|Отправить письмо подтверждения|Auth Service отправляет запрос в Email Service для отправки письма подтверждения.|
|12|Email с подтверждением|Email Service отправляет пользователю письмо для подтверждения регистрации.|
|13|Регистрация успешна|Auth Service сообщает Web Interface об успешной регистрации.|
|14|Показать сообщение об успешной регистрации|Web Interface отображает пользователю сообщение о завершении регистрации.|

```
DB --> Order : Заказ создан

Order -> Payment : Запрос на оплату
Payment --> Order : Результат оплаты (успешно)

Order -> DB : Обновить статус заказа (оплачен)

Order --> UI : Подтверждение заказа
UI --> Customer : Показать сообщение\n"Заказ успешно создан"

@enduml
```

### Диаграмма последовательности (Оплата заказа)

![[Pasted image 20260314233822.png]]
```
@startuml
autonumber
actor Customer as "Покупатель"
participant "Web Interface" as UI
participant "Order Service" as Order
participant "Payment Service" as Payment
database "Database" as DB
participant "Notification Service" as Notify

Customer -> UI : Выбрать способ оплаты
UI -> Order : Отправить запрос на оплату заказа

Order -> DB : Получить данные заказа
DB --> Order : Информация о заказе

Order -> Payment : Создать платеж

Payment -> Customer : Запросить ввод платежных данных
Customer -> Payment : Ввести платежные данные

Payment -> Payment : Проверить платежные данные
Payment -> Payment : Выполнить транзакцию

Payment --> Order : Результат оплаты (успешно/ошибка)

alt Оплата успешна
    Order -> DB : Обновить статус заказа (оплачен)
    Order -> Notify : Отправить уведомление об оплате
    Notify --> Customer : Email / сообщение об успешной оплате
else Ошибка оплаты
    Order -> UI : Сообщить об ошибке оплаты
    UI --> Customer : Показать сообщение об ошибке
end

@enduml
```
